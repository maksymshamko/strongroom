## §2 Contract decisions the spec left open

1. **Live-node filter.** Every read predicate gains `AND "deletedAt" IS NULL`,
   exposed as `excludeDeleted` on the repository's list/search options. This is
   possible because §2.1 stamps the whole deleted subtree, so a descendant
   answers for itself; the earlier path-prefix approach needed an extra
   `findTrashRoot` query on every request and silently missed
   `listDataRooms`, which had no path filter at all.
2. **Purge claiming.** `purgeExpired` selects candidate ids first, then deletes
   them one transaction at a time. A second runner finds nothing because the row
   is gone, so no lock or lease is needed for the spec's idempotency claim.
3. **Restore is a move.** `TrashService.restore` reuses `NodeService`'s reparent
   and rollup paths rather than duplicating them, which is what makes the §6.4
   conflict protocol apply to restore for free.
4. **`deletedFromLabel` for a data room** is the literal string `"Data rooms"`,
   matching the dashboard's own heading.
5. **Scheduler.** A bare `setInterval` registered in an `OnModuleInit`, cleared
   on `OnModuleDestroy`, skipped when `NODE_ENV=test` so the suite controls
   purging explicitly.
6. **Theme flash.** The pre-paint script is inlined in `layout.tsx` via
   `dangerouslySetInnerHTML` — the only way to run before first paint in the App
   Router.
7. **Breadcrumb collapsing** is computed from the segment array the API already
   returns; no new endpoint.

## §4 Gate 4 — verification against the spec

Walked spec 003 section by section against §3.

**Every section appears.** §4.2, §2.9 and §9 appear with an explicit "no test,
and why".

**Every decision this plan makes was left open by the spec:**

| Plan decision | Spec status | Verdict |
|---|---|---|
| `excludeDeleted` predicate (§2.1) | §2.1/§2.8 fix the stamping rule and the filter's meaning, not its name | Plan detail. OK |
| Select-then-delete purge claiming (§2.2) | §2.7 requires idempotency, names no mechanism | Plan detail. OK |
| Restore reuses the move path (§2.3) | §2.6 states restore is the delete reversed and defers to §6.4 for conflicts | Plan follows spec. OK |
| `"Data rooms"` label (§2.4) | §2.4 states this literal | Plan follows spec. OK |
| `setInterval`, disabled under test (§2.5) | §2.7 says hourly in-process, silent on test behaviour | Plan detail. OK |
| Inline pre-paint script (§2.6) | §3.2 requires no flash, names no mechanism | Plan detail. OK |

**Disagreements found: one.** Spec §2.5 says `GET /trash` returns
`{ node, items }` where `items` is a `Page<TrashItemDto>`, but the §2.1 empty
state test expects `items` to be an empty **array**, not `{ items: [], nextCursor }`.
Left as written in the spec: `items` is the page's array and the cursor rides
alongside it as `nextCursor` at the top level, so the response is
`{ node, items, nextCursor }`. Resolved **in the spec** (§2.5 now states the
three-key shape) rather than by reshaping the test.

**No plan step invents behaviour the spec does not describe.** Gate 4 passes.
